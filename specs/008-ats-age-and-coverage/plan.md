# 008 — план

## Шаг 1. Метка ATS-лида
Три парсера (`parse_greenhouse_boards`, `parse_lever_boards`, `parse_ashby_boards`)
добавляют `"from_ats": True` в словарь лида. Метка живёт только в памяти прогона:
в SQLite не пишется, схема не меняется.

## Шаг 2. Исключение в lead_fresh
Ранний `return True` для `from_ats` **после** проверки `CLOSED_PATTERNS`, но **до**
проверки `posted_at`. Порядок важен: закрытые вакансии отсекаются как раньше.

## Шаг 3. Расширение реестра
Отбор кандидатов: скрипт-пробник бьёт в публичные API Greenhouse/Lever/Ashby,
оставляет борды, где есть вакансии с заголовком ops/kyc/compliance/settlement/
treasury/payments и `passes_location`. Мусор (engineer, marketing, sales) — мимо.
Добавлять и борды, где сейчас 0 подходящих вакансий, но профиль верный и опрос
дешёвый.

## Риск
Долго висящая вакансия может оказаться «забытой» в борде и уже неактуальной.
Митигация: `CLOSED_PATTERNS` ловит явные маркеры; письмо всё равно уходит
вручную, оператор видит вакансию до отправки.
