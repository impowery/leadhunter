# 008 — ATS age-фильтр и покрытие бордов

## Проблема

Поток вакансий обвалился в 45 раз на стыке W45/W46 (2948 → 68 собранных за неделю).
Разбор 26.11 дал три причины, две из них чинятся здесь:

1. **Баг age-фильтра.** `lead_fresh()` отбрасывает лиды старше `MAX_LEAD_AGE_DAYS=30`
   по `posted_at`. Для ATS-бордов дата берётся из `updated_at`/`first_published`,
   но Greenhouse/Lever/Ashby отдают в API **только открытые** вакансии. Долго
   висящая вакансия — открытая, а не устаревшая. Потеря: Alpaca
   «Crypto Operations Associate - APAC» (`4431262004`, updated 2026-09-29, 57 дней)
   не попала в базу никогда.
2. **Мало ATS-бордов после отключения 17 источников** (спека 007). Нужно наращивать
   покрытие профильными fintech/crypto бордами, без мусора.

Третья причина (job-борды исчерпались, дедуп режет старое) — не здесь.

## Решение

1. Лиды трёх ATS-парсеров помечаются `from_ats: True`. `lead_fresh()` для них
   пропускает проверку возраста, но **сохраняет** проверку `CLOSED_PATTERNS`
   (явные маркеры «no longer accepting applications» и т.п.).
2. В `sources.json` добавляются борды, отобранные вручную: только компании
   с профилем crypto/payments/banking ops. Каждый кандидат проверен живым
   запросом к API (существует ли борд, сколько вакансий, сколько проходят
   `_crypto_ops_relevant` + `passes_location`).

## Не входит

- Возврат отключённых источников (Jobicy, @jobstash, HN, Remotive).
- Изменение дедупликации и порога доставки.
- Судьба третьей причины обвала.

## Приёмка

- APAC-вакансия Alpaca сохраняется и доставляется (score ≥ 6).
- RSS/Telegram-лиды старше 30 дней по-прежнему отбрасываются.
- ATS-лид с текстовым маркером закрытия по-прежнему отбрасывается.
- `sources.json` валиден, бот стартует без Traceback, новые борды парсятся.
