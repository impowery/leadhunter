# Spec 006: apply pipeline (autofill 2.0)

## Проблема

`apply/autofill.py` заполняет форму по одному URL из буфера обмена и не умеет:
заполнять `bio` и `skills` (в профильных формах это отдельные поля), проходить
кнопку «Apply» у Greenhouse/Ashby/Workable, работать очередью вакансий,
кэшировать письмо локально, вести лог откликов и защищаться от повторной отправки.

## Цель

Довести путь «взял вакансию → форма заполнена» до 1-2 действий пользователя,
не добавляя автоподачу. Submit всегда нажимает человек.

## Требования

1. `apply/profile.json`: поля `bio` (текст) и `skills` (список через запятую).
2. `autofill.py` заполняет `bio` и `skills`, включая tag-инпуты (Enter после каждого тега).
3. Адаптеры ATS: Greenhouse (`job-boards.greenhouse.io`, `boards.greenhouse.io`),
   Ashby (`jobs.ashbyhq.com`), Workable (`apply.workable.com`), Lever (как сейчас).
   Адаптер открывает форму, если она за кнопкой.
4. Письмо кэшируется в `apply/letters/<sha1(url)>.txt`; SSH к VPS только при промахе.
5. `apply/queue.py` собирает очередь из базы VPS (только чтение): лиды с готовым
   письмом, по убыванию fit, без уже отправленных.
6. `apply/next.py` берёт следующую вакансию из очереди, подставляет письмо,
   открывает браузер и заполняет форму.
7. `apply/applied.json` — лог откликов; повторная вакансия помечается и пропускается.
8. Опционально `--steps N`: нажать «Continue/Next» до N раз (по умолчанию 0).

## Границы

- Submit не нажимается никогда.
- LinkedIn, Upwork, Indeed не поддерживаются: автоподача там нарушает правила.
- Прод-бот не меняется: очередь читается из существующей базы, деплой не нужен.
- Персональные файлы (`queue.json`, `letters/`, `applied.json`) не попадают в git.

## Критерии готовности

- `py_compile` всех изменённых файлов.
- Оффлайн-проверка: кэш письма, лог откликов, разбор очереди.
- Живая проверка: headless-заполнение реальной Greenhouse-формы (Alpaca) с
  отчётом «filled/skipped» и скриншотом, без отправки.
- Спековый converge с фактическим результатом.
