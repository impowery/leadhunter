# 005 — Audit-проход для писем

## Зачем
Письмо владельцу может содержать выдуманный опыт, общие фразы и тире. Второй вызов проверяет черновик
(maker-checker) и помечает или исправляет его до отправки.

## Что меняется
- `audit_kit(lead, kit)`: второй вызов LLM (tier quality, claude-haiku-5.5) проверяет письмо и ответы
  против профиля и вакансии. Возвращает ok, problems (до 6) и исправленное письмо, если есть проблемы.
- `build_application_kit` вызывает audit и подменяет письмо на исправленное.
- В таблицу `kits` добавлен столбец `audit` (JSON: ok, problems).
- В Telegram-сообщении пакета строка «audit: pass» или «audit: fixed N issue(s)».

## Требования
- Audit не блокирует доставку пакета: при ошибке LLM пакет уходит без audit (с предупреждением в логе).
- Audit не выдумывает факты: исправленное письмо берётся только из профиля.
- Письмо после audit: 110–160 слов, без em/en dashes.
- Модель и цена — через существующий `_llm_chain("quality")`, без новых переменных окружения.

## Вне рамок
- Audit для `generate_application` (одиночный черновик из MCP и команды /app) — отдельный шаг, если понадобится.
- Batch-approve, Freelancer API (пункты 2 и 3 из обзора LavoroAI).
- Изменение скоринга, парсеров, доставки гостям.

## Критерии приёмки
- py_compile локально и на VPS проходит.
- На 3 эталонных вакансиях (подходящая, частичная, мусор) audit возвращает ok/problems, без исключений.
- Пакет в Telegram содержит строку audit; в таблице kits заполнен столбец audit.
- Лог после перезапуска без Traceback.
